# 3D 팝업스토어 지도: 기획서 (3단계)

> `AI-워크플로우.md` 3단계의 결과물이에요. 확정된 내용과 아직 정해야 할 내용을 나눠 적었어요.
> 작성일: 2026-11-26

## 한 줄 정의

평범한 2D 지도 위에서 **팝업스토어 건물만 3D 입체로 솟아오르고**, 건물을 누르면 **청사진(블루프린트) 스타일로 층별 이벤트**와 연락처를 보여 주는 부산 팝업스토어 모바일 웹앱.

## 기능

| 구분 | 기능 | 비고 |
|---|---|---|
| MUST | 지도는 2D, 팝업스토어 위치에만 3D 건물 표시 | 다른 건물은 납작하게 둬서 팝업만 눈에 띄게 해요 |
| MUST | 3D 건물은 실제 건물 색으로 표시 | 색은 DB에 직접 입력해요 (아래 "확인할 점 2") |
| MUST | 건물을 누르면 정보 패널: 이름, 기간, 주소, 영업시간, **전화번호(누르면 전화 걸기)** | |
| MUST | 층마다 어떤 이벤트가 있는지 확인 | 청사진 레퍼런스처럼 층을 나눠 보여 줘요 |
| MUST | 길찾기 | 방식은 아래 "확인할 점 1"에서 정해야 해요 |
| SHOULD | 버튼은 둥글고 크게, 확실히 보이게 | 레퍼런스 하단 버튼 바처럼 |
| COULD | (미정) | 아이디어: 3D↔2D 전환, 층 클릭 시 해당 층만 강조, 곧 끝나는 팝업 표시, 공유 링크 |

## 디자인 레퍼런스: 청사진

첨부한 "청사진 (LIFE BLUEPRINT)" 화면의 **분위기와 구성**을 참고해요. 화면을 그대로 베끼지는 않아요.

가져올 것:
- 남색 바탕에 하늘색 선, 모눈 격자가 있는 **설계도 느낌**
- 상단의 **표제란(TITLE BLOCK)**: 도면명 대신 팝업 이름, 작성자 대신 운영사, 날짜 대신 운영 기간, 공정률 대신 **남은 기간 막대**
- 오른쪽 **층 표시(1F, 2F…)와 층별 내용**
- 하단의 **둥근 버튼 바**: 예) `시점` (지도 각도 초기화), `길찾기`, `층`, `전화`
- 오른쪽 위의 `3D 입체도 / 2D 평면도` 전환

바꿀 것:
- 인생 목표 대신 **팝업 이벤트**를 층별로 표시해요 (예: 1F 굿즈 판매, 2F 포토존, 3F 사인회)
- 건물 하나만 있는 화면이 아니라 **지도 위에 여러 건물**이 있어요. 건물을 누르면 청사진 패널이 열려요.

## 화면 목록

1. **메인 지도**
   - 2D 지도를 살짝 기울인 상태로, 팝업 위치에만 3D 건물이 서 있어요.
   - 지도 색도 청사진 톤(남색 바탕, 하늘색 도로)으로 맞춰요.
   - 하단에 둥근 버튼 바가 있어요.
2. **팝업 상세 (청사진 패널)**
   - 아래에서 올라오는 패널이에요.
   - 표제란(이름, 운영사, 기간, 남은 기간 막대), 층별 이벤트 목록, 전화·길찾기 버튼이 있어요.
   - 층 이름을 누르면 지도 위 3D 건물에서도 그 층이 밝게 빛나요.
3. **빈 상태 / 로딩 / 에러**
   - 불러오는 중: "도면 불러오는 중…"
   - 팝업 없음: "이 근처엔 아직 착공된 팝업이 없어요"
   - 에러: 다시 시도 버튼

### DB는 Supabase로 가요

질문에 대한 답: **Supabase가 맞아요. 다른 걸로 바꿀 이유가 없어요.**
- 이미 한 번 연결해 봤어요 (방명록 히스토리 `d95e25b`).
- 무료이고, 웹 화면에서 표를 엑셀처럼 직접 채울 수 있어요. 팝업 20~30개를 손으로 넣기 편해요.
- 대안인 Firebase도 되지만, 층별 이벤트처럼 표와 표가 연결된 데이터는 Supabase(표 기반 DB)가 더 자연스러워요.

## 3D 구현 방법 (설계 메모)

MapLibre에는 바닥 모양을 높이만큼 위로 밀어 올리는 기능(`fill-extrusion`)이 있어요. 이 기능의 **시작 높이(base)와 끝 높이(height)를 층마다 다르게** 주면, 건물 하나를 **층 블록 여러 개를 쌓은 모양**으로 그릴 수 있어요.

- 1층은 0~4m, 2층은 4.2~8.2m처럼 층 사이에 살짝 틈을 두면 청사진처럼 층이 구분돼 보여요.
- 층 블록 하나하나가 따로 눌리기 때문에 "몇 층을 눌렀는지" 바로 알 수 있어요.
- 색은 `building_color`를 쓰고, 선택한 층만 밝은 하늘색으로 바꿔요.
- 건물 바닥 모양은 처음에는 좌표를 중심으로 한 사각형으로 만들어요. 실제 건물 윤곽을 쓰는 건 COULD로 미뤄요.
- Three.js 같은 별도 3D 도구가 필요 없어서 하루 안에 만들 수 있는 난이도예요.

## 결정 사항 (2026-11-26 확정)

### 1. 길찾기: A안 (외부 지도 앱으로 넘기기), 단 우리 UI는 카카오맵과 다르게

- `길찾기` 버튼을 누르면 바로 넘어가지 않고, **우리 청사진 스타일의 "출발 전 확인" 시트**가 먼저 떠요.
  - 시트 내용: 목적지 이름, 현재 위치에서의 직선 거리, 걸어서 예상 시간(대략), 영업 중/종료 표시
  - 지도 위에는 내 위치 → 팝업까지 하늘색 **점선**(설계도의 치수선 느낌)을 그려요.
  - 시트 아래에 `카카오맵으로 안내` / `네이버지도로 안내` 버튼을 둘 다 둬서, 특정 지도 앱에 묶인 느낌을 줄여요.
- **한계**: 버튼을 누른 **뒤에 열리는 화면은 카카오맵(또는 네이버지도) 자체 화면**이라 색이나 UI를 바꿀 수 없어요. 우리가 디자인할 수 있는 건 넘어가기 **전까지**예요.

### 2. 건물 색: 최근 사진에서 색 코드 추출

- 순서
  1. 사람이 팝업 건물의 **가장 최근 사진**을 찾아요. 우선순위는 팝업 공식 SNS·기사 사진 → 네이버/카카오 로드뷰예요. 로드뷰는 촬영 날짜를 확인하고, 오래됐으면 SNS·기사 사진을 우선해요.
  2. 사진을 `tools/photos/` 폴더에 저장해요. 파일명은 팝업 id로 해요.
  3. **색 추출 스크립트**(Claude가 만들어요)가 사진에서 대표색을 뽑아요. 벽, 포인트(간판), 지붕 세 가지예요.
  4. 사람이 결과를 보고 확인한 뒤 DB에 넣어요.
- **한계**: 로드뷰나 지도 API에서 사진을 자동으로 가져오는 건 어려워요. 보안 정책상 화면 밖으로 사진 픽셀을 꺼낼 수 없고, 약관 문제도 있어요. Google Street View API는 유료이고 한국 촬영 범위가 좁아요. 그래서 **사진 찾기는 사람이, 색 뽑기는 스크립트가** 하는 반자동 방식으로 해요.
- **저작권**: 사진 자체는 앱에 넣지 않고, **뽑아낸 색 코드만** 써요. 사진 원본은 Git에 올리지 않아요(`.gitignore`).

### 3. 팝업 데이터: 실제 부산 팝업

- 대회 직전(1~3일 전)에 **실제로 열려 있는 부산 팝업**을 조사해서 넣어요. 너무 일찍 조사하면 끝난 팝업이 섞여요.
- Claude가 웹 검색으로 후보 목록을 만들고, 사람이 공식 SNS에서 주소, 기간, 전화번호를 확인해요.
- **층별 이벤트 정보가 없는 팝업**은 층 블록을 나누지 않고, **건물 겉면 디자인**(실제 색, 층수만큼의 높이, 창문 띠)만 입체로 그려요. 상세 패널의 층별 이벤트 칸은 숨겨요.
